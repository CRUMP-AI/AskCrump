# Ask Crump 5.9.75 document output-proof release

Date: 2026-08-29

Production version: 5.9.75

Feature commit: `7d82066`

Production deployment: `dpl_CnHRGvnptVZE7Qqc6X4M9VEk44sh`

## Accountable outcome

Let a prospective document user inspect a representative editable result before creating an
account, while keeping the proof truthful, synthetic, generated through the current exporter, and
clearly separate from a customer testimonial or guaranteed outcome.

The release does not claim conversion or universal document-quality lift. Its accountable delivery
outcome is that the public document page no longer asks a visitor to rely on copy alone.

## Evidence and source

The protected production acquisition and artifact journey remained empty, so no external-account
behavior was invented and no synthetic production account or event was created. A comparison of
the public acquisition pages found a deterministic trust gap: the presentation and résumé pages
exposed current rendered output, while the document page described Word/PDF output without showing
it.

The example was generated by Ask Crump's current Word exporter from a wholly fictional
launch-readiness brief added to the reproducible internal quality-sample script. The resulting
`.docx` was opened read-only in Microsoft Word, rendered to PDF, and rasterized at 1,224 by 1,584
pixels for complete visual inspection. The Word, PDF, and temporary render stayed outside the
repository; only the reviewed public PNG was added.

The first business-document render exposed a real pagination defect: a table header could be left
alone at the bottom of a page while its data began on the next page. The exporter was corrected
before the marketing proof was accepted. Word table rows now carry the native no-split property,
cell paragraphs stay together, and a header row stays with its first data row.

- Replaced résumé-only proof styles with one shared responsive artifact-proof component.

- Advanced the document page's sitemap modification date.
- Advanced the application to 5.9.75, native build 50975, and PWA cache revision 109.

## Safety and scope boundaries

The release did not change:

- authentication, registration, verification, session authority, cookies, or account recovery;
- customer documents, files, conversations, private Library data, prompts, or model routing;
- pricing, plans, credits, checkout, Stripe, RevenueCat catalog identifiers, or entitlements;
- Supabase schema, RLS, production analytics records, developer accounts, signing, or store
  submission.

The sample names, dates, owners, statuses, and launch decision are fictional. Production
verification used public GET requests only and created no account, prompt, artifact, checkout, or
funnel mutation.

## Measurement decision

Treat `source=document-proof` as a discoverable acquisition path, not proof of lift. Observe the
document page's first-party CTA and the protected `SignupIntent` → `SignupStarted` → verified
account → document artifact journey for at least 14 days and 50 qualified referred visitors before
attributing an effect. Diagnose any legitimate failed journey sooner, but do not create synthetic
production users or infer a platform click-through rate without impression data.
